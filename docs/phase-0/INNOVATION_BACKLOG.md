# Evidence-Driven Innovation Backlog

See INNOVATION_GUARDRAILS.md before promoting any backlog item.

These ideas improve trust or counterparty experience without expanding V1 into a speculative marketplace. Each item needs a named hypothesis, safe fixture, baseline, and kill criterion before implementation.

## Now — first vertical slice

1. **Synthetic Twin onboarding** — generate a safe mirror of the real adapter contract so every participant can prove compatibility before data or privileges are attached.
2. **Counterparty Trust Passport** — reuse scoped identity, capability, policy, and review evidence across workspaces instead of repeating onboarding.
3. **Evidence Inbox** — give reviewers/verifiers a prioritized list of exactly what changed, what is missing, and which decision is requested.
4. **Reproduction Diff** — compare program, environment, data lineage, hardware, numerical settings, and outputs in one explanation rather than exposing two raw logs.
5. **Counterexample Companion** — create a challenge checklist beside every important claim at definition time, not after a public failure.
6. **Plain-language receipt layers** — one receipt with Explorer, Scientist, Engineer, Operator, Security, and machine-readable views rather than duplicated sources of truth.
7. **Visible demo provenance** — every synthetic number links to its fixture/generator and is labeled `DEMO / SYNTHETIC`.

## Next — after receipt conformance

1. **Policy translator** — convert institutional constraints into a reviewable execution/data policy while preserving the original source and human approval.
2. **Outbound worker connector** — enable bring-your-own compute through short-lived task leases and egress-only connections.
3. **Portable evidence bundle** — export the minimal artifacts required for independent reproduction with rights/classification metadata.
4. **Reliability-aware advisor** — suggest adapter/solver/environment choices using cohort evidence, sample size, uncertainty, and failure history; never auto-lower acceptance rules.
5. **Incident-to-regression pipeline** — turn a confirmed operational or scientific failure into a proposed test/runbook change with traceable review.
6. **Procurement trust packet** — assemble current architecture, controls, dependency inventory, test results, data flow, and incident contact from source evidence.
7. **Review reciprocity** — let an institution accept verified evidence from another reviewer while preserving its right to require local checks.

## Later — only with demonstrated demand

1. Hardware-backed worker/verifier identity and workload attestation.
2. Confidential-computing evidence for specifically justified protected workloads.
3. Privacy-preserving aggregate reliability statistics with a documented threat model.
4. Off-chain sponsor accounting, then a settlement pilot after duplicate/refund/budget invariants pass.
5. Cross-institution federation and policy negotiation.

## Kill criteria

Stop or narrow an idea if it requires hidden correctness logic, unverifiable claims, new long-lived secrets, broad production access, restricted-data publication, acceptance-rule dilution, or operating cost unsupported by a validated customer problem.
